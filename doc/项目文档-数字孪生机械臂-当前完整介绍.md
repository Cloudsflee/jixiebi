# 项目文档：数字孪生机械臂（当前完整介绍）

版本：2026-04-24  
适用范围：`STM32 + CH340 + Web 数字孪生联调` 当前仓库实现

---

## 1. 项目概述

本项目面向 4 关节机械臂的“低成本数字孪生联调”场景，目标是建立一条可重复的工程链路：

- 前端可视化控制与参数校准；
- 网关完成 WebSocket 与串口协议桥接；
- STM32 执行总线舵机控制与状态回读；
- 3D 模型与实机动作尽量同步，减少调试阶段无效试错。

当前定位是“可运行、可演示、可迭代”的工程 MVP，不是量产级控制系统。

---

## 2. 项目目标与价值

## 2.1 目标

- 打通 `Web -> Gateway -> STM32 -> 舵机` 控制闭环。
- 支持关节参数在线调节与写回 `joints.json`。
- 支持模型加载、关节层级驱动、轴线与轴心校准。
- 支持演示级正逆解与伪有限元可视化。

## 2.2 价值

- 降低机械臂调试中的盲调成本；
- 把风险前移到虚拟空间；
- 为后续真实机构参数化、URDF 导出和更高精度算法提供基础。

---

## 3. 已确认硬件边界

- 控制板：开源 6 路舵机控制器。
- 舵机：总线舵机（非原配 PWM 舵机）。
- 通信：PC 通过 CH340 串口连接开发板，常用 `COM5`。
- 目标机械结构：4 轴机械臂（J1~J4）。

约束：后续默认采用“总线舵机链路”，不回退为原配 PWM 方案。

---

## 4. 软件总体架构

## 4.1 架构分层

- 固件层（STM32）：执行舵机命令、读取位置电压、处理文本协议。
- 网关层（front/gateway）：WebSocket <-> 串口桥接；支持 `joints.json` 直读直写。
- 前端层（front/web）：控制面板 + 3D 可视化 + 参数编辑 + 演示 IK/FEA。

## 4.2 数据流

- 控制流：Web -> Gateway -> UART -> STM32 -> 舵机
- 状态流：舵机 -> STM32 -> UART -> Gateway -> Web
- 配置流：Web -> Gateway -> `front/web/joints.json`

## 6. 固件与通信协议

## 6.1 固件能力（当前）

- 总线舵机常用接口已具备：
  - `Move`
  - `ReadPosition`
  - `ReadVin`
  - `ReadID / SetID`
  - `LoadOrUnload`
- 已支持 UART 文本联调协议（与底层舵机帧并存）。

## 6.2 文本协议（Gateway <-> STM32）

- 下发：
  - `PING`
  - `M,<id>,<pos>,<time_ms>`
  - `Q,<id>`
  - `V,<id>`
- 回包：
  - `OK`
  - `ERR,<code>`
  - `P,<id>,<pos>`
  - `V,<id>,<mv>`

## 7. 网关（front/gateway）说明

## 7.1 功能

- WebSocket 服务端（默认 `ws://127.0.0.1:8787`）。
- 串口管理（默认 `COM5 @ 9600`）。
- 转发 JSON 命令到 STM32 文本协议。
- 广播 MCU 回包给所有 Web 客户端。
- 提供 `joints.json` 读写 API（不依赖串口开启）。

## 7.2 WebSocket 指令（当前）

- `{"type":"move","id":1,"pos":500,"time":300}`
- `{"type":"query","id":1}`
- `{"type":"vin","id":1}`
- `{"type":"ping"}`
- `{"type":"raw","line":"M,1,500,300"}`

配置接口：

- `config_read`
- `config_write`

这使前端“写入选中关节”可以在网关在线时直接写文件，不再弹本地文件选择器。

---

## 8. 前端（front/web）核心能力

## 8.1 基础联调能力

- WebSocket 连接、状态展示、日志输出。
- J1~J4 参数控制与指令发送。
- 位置与电压查询。
- 默认位姿回归、批量查询。

## 8.2 3D 可视化能力

- Three.js 加载 STL 并按 `base/j1/j2/j3/j4` 建立层级。
- 关节旋转与模型联动显示。
- 轴线显示与选中关节高亮。

## 8.3 轴线/轴心校准能力（近期强化）

- 支持父坐标系轴线锁定（`motionLocks.parentAxisByTarget`）。
- 支持 3D 拖拽轴线方向。
- 支持点选模型表面生成“外->内”轴线。
- 支持固定轴线位置。
- 支持轴心沿轴线约束滑动。

以上能力用于降低“轴向错位导致的模型乱飞”问题。

## 8.4 配置写回能力

- `Write selected J`：仅写当前关节参数。
- `Write all`：写全部关节参数。
- 网关在线时优先走 `config_write`，实现“无需手选文件”的直写。

## 9. joints.json 配置说明（关键）

`front/web/joints.json` 是当前系统的核心配置文件，主要包含：

- `parts`：STL 文件与关节目标分组映射。
- `joints[]`：关节定义（servoId、轴向、限位、零位、pivot、映射等）。
- `physicalKinematics`：闭链几何参数（当前默认关闭）。
- `demoKinematics`：演示 IK 模型参数。
- `demoFea`：演示伪 FEA 模型参数。
- `demoRuntime`：演示运行态参数。
- `assemblyLock`：装配锁定策略。
- `motionLocks`：运动轴锁定策略。

## 10. 闭链与装配策略（当前状态）

## 10.1 physicalKinematics（真实闭链求解）

- 已具备数据结构与求解入口。
- 当前 `enabled=false`，默认不强制启用。
- 适用于“已从 CAD 提取准确孔位与连杆参数”的场景。

## 10.2 assemblyLock（装配稳定优先）

当前配置启用：

- `assemblyLock.enabled=true`
- `disableCouplings=true`

目标是先保证演示时结构稳定，不让模型散架乱飞。

## 10.3 motionLocks（轴向约束）

当前至少对 J2 做了父坐标轴锁定，保证“J2 相对 J1 的轴向行为”更可控。

## 11. IK + 伪 FEA 演示模块

## 11.1 Demo IK

文件：`front/web/modules/demo_kinematics.js`

- 提供前向运动学与逆向运动学函数。
- 输入目标点后可解算 J1~J4 的演示角度。
- 目标是“快速视觉可解释”，不是高精度工业逆解。

## 11.2 Demo Pseudo FEA

文件：`front/web/modules/demo_fea.js`

- 基于杠杆臂、截面强度、柔顺参数做伪应力评估。
- 输出应力比、热度比、变形估计，用于可视化上色与形变表达。
- 明确属于演示层风险提示，不替代真实有限元分析。

---

## 12. URDF 与 SLDASM 相关能力

## 12.1 当前可做

- 可基于 `joints.json` 生成 URDF 骨架。
- 可生成 SLDASM 清单文件用于模型对齐检查。

命令示例：

- `node front/web/tools/build_sldasm_manifest.js`
- `node front/web/tools/generate_urdf_from_joints.js`

## 12.2 当前限制

- 在未安装 SolidWorks COM / FreeCAD 解析器时，无法直接完整解析 SLDASM mate 约束。
- 因此“严格装配约束级 URDF”仍需额外导出中间数据或专用解析环境。

## 13. 当前运行方式（推荐）

## 13.1 固件

- 编译：`make -f gcc/Makefile all`
- 烧录：`make -f gcc/Makefile flash FLASH_PORT=COM5 FLASH_BAUD=115200`

```bash
cd front/gateway
cmd /c npm install
cmd /c npm start
```

## 13.3 前端

```bash
cd front
python -m http.server 8090
```

## 15. 风险与应对

- 风险：模型与实物轴系不一致导致动作异常。  
  应对：轴线锁定 + 点选建轴 + 沿线拖轴心 + 参数回写闭环。

- 风险：串口链路抖动造成控制体验差。  
  应对：网关节流、轮询策略、错误码追踪。

- 风险：演示算法被误解为工程最终结论。  
  应对：文档和视频中明确“演示估算/非最终工况”。
